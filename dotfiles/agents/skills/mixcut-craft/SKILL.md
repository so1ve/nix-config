# 高燃混剪剪辑心得

这里是通用方法，适用于任何作品的踩点混剪：游戏的 CG/PV/过场、动画、影视预告。

- 素材归属与剧情核实见 `mixcut-story-attribution`，工具与渲染见 `mixcut-pipeline`。
- 完整案例（终末地 × Warriors，含每轮被否的做法和最终的衔接表）见 [references/endfield-warriors.md](references/endfield-warriors.md)。
- 角色个人向案例（终末地 · 诀 × Game of Survival，含故事线、修订过程和衔接表）见 [references/endfield-arcane.md](references/endfield-arcane.md)。

## 默认标准

以下是用户在实际项目中明确提出的偏好。换作品也照此执行，除非用户另有说明。

- **画面里不加文字。** 片头标题、章节/版本标签、BGM 署名、片尾字卡、歌词都不要。双语歌词、黑边里的花体歌词都试过，最后都被去掉。剧情推进靠画面内容和剪辑组织来交代。
- **讲剧情历程的混剪只用主线。** 角色个人剧情（角色 PV、角色 EP、活动过场）不放；用户点名的例外才用。角色个人向剪辑相反，个人剧情是主料。
- **每个镜头都要有张力。** 意义不明的平静镜头不要。
- **章节衔接要"灵性"**：利用人物的动态、移动方向、画面位置切到下一镜，比如同样的动作、类似的位置。
- **结尾卡点要准**：英雄镜头落在全曲最后一个重拍上，音乐实际结束就直接结束。
- **投稿标题用原作官方文案**，简短有力，例如游戏宣传片里的一句台词或口号。不要自己起的短名字，也不要自己写的长文案。

## 反面清单

以下做法都被用户否过：

- 镜头之间用叠化、高光烧穿、水墨晕开、白场，被评价为"一堆平滑过渡"。
- 甩镜、刀光劈开、推进传送门这类转场，被评价为"俗套的机械转场"。
- 华丽的拼贴效果，例如把一个画面切成四块从四个方向飞入。用户说这类效果一部视频最多用一次，而且必须理解到位，"没必要硬用"。
- 从激烈画面直接切到不相干的平静画面，"太突兀"。
- 结尾等到音乐完全静音才结束；黑边合拢、"闭眼"式收尾、去饱和定格。
- 把两段不同的镜头左右拼接，"效果太差"。分屏只在同一镜头存在两个版本时才做，例如男女主角版本的同一镜头。
- 文字动画（字距逐渐展开）、难认的花体字。
- 实机游戏画面混进 CG 战斗：观感廉价，CG 与过场优先。版本 PV 里的角色技能展示段也一样：只取近景、特写和大特效镜头，俯视角度和竞技场远景像实机，不用。
- 官方角色名片、立绘展示卡（大字角色名、星级、属性图标）：剪进片子里"莫名其妙"。
- 把几个视频的镜头逐个穿插：前后镜头不属于同一场戏，衔接僵硬、没有剧情联系。
- 叠着界面图形的镜头：音乐视频（EP、MV）里的准星、面板、进度条、HUD 圆环、方格，"没有沉浸感"。画面里的法术阵、技能光效属于场景，可以用。
- 模糊、卡顿的镜头。常见原因：慢放倍数太大（插帧在快速动作上变形），素材本身是 30 fps，被放大裁切（为躲字幕）。动作镜头尽量原速或不低于 0.6 倍；0.5 倍以下只给近乎静止的画面。
- 高潮用小规模战斗（和小 boss 交手），结尾落在意义不明的画面上：被评价为"全片比较无力"。
- 为了插别的素材，把原片里一组有力的衔接拆开（例如挥刀 → 蓝光炸开）：用户记得原来的效果，会要求恢复。

## 结构：跟着歌走

1. **先量歌。**
   - 拟合恒定节拍网格（BPM 和相位）。
   - 按小节测响度和低频能量，标出前奏、主歌、副歌、空拍小节（break）、落点（drop）、最后一个重拍，以及音乐真正衰减下去的时刻。
   - 同时对齐歌词时间轴（LRC），用来安排有意义的画面。
2. **镜头长度跟段落走，不要每拍一切。**
   - 前奏、序章：2–6 拍一镜，可以慢放、慢推。
   - 主歌：1–2 拍一镜。
   - 副歌：大多 1 拍一镜，冲击处半拍。大副歌前可以放一串 1/4 拍的人物特写快闪，全片一两次即可。
   - break：留白。放一两个慢镜头（推近眼睛、凝视），然后在 drop 第一拍硬切到全片最猛的动作，配冲击帧和震屏。
   - 尾声：各章节一镜快速回顾，接群像，英雄镜头落在最后一个重拍上。
   - 最后一段副歌是全片高潮，要用全片最震撼的素材：剧情的决战、角色的终极技能、规模最大的 CG。按"决战 → 全力爆发 → 最后一击"递进，英雄镜头接在最后一击之后（例如出招后站定），这样结尾才有意义。
3. **把动作峰值放在鼓点上。** 找到镜头的运动峰值或最亮帧，让它落在剪点或某一拍上，而不是从镜头开头机械截取。
4. **歌词意象可以对画面**（"built this town" 对建设场景），但不能为此牺牲张力。
5. **调色要克制。** 每个章节一个色调，全片统一一层很轻的 finish（高光柔光、暗角、细颗粒）。局部风格化手段（比如灰色世界只留红色）只用在少数场次。

## 叙事组织：不用文字讲清剧情

- **按时间线排章节。** 每章依次给出：标志性地貌或场景 → 新登场的人物 → 这一章的冲突 → 高潮。观众靠地貌和人物的变化感知"进入了新篇章"。
- **一段一场戏。** 每个段落尽量取自同一场景，按原片顺序剪，让前后镜头有因果（看见 → 反应，出招 → 命中）。换场景放在段落交界，用有动机的硬切或闪光衔接。闪回和快闪特写是例外。
- **角色个人向剪辑**：先把该角色的素材按剧情排成一条线（例如：归乡 → 往事 → 与宿敌并肩 → 直面心结 → 放下 → 自己的决战），再按歌的段落分配。个人剧情（角色 PV、EP、干员叙事）此时是主料。
- **先读懂每个素材。** 动手前把每个源视频按约每秒一帧完整看一遍，写下它的场次顺序：谁、在哪、发生了什么、哪里是闪回。官方过场常把一段剧情拆成好几个快切子镜头，自动检测会把它们合成一个"镜头"。读完写进 `catalog/scenes/<id>.md`（格式见 `mixcut-story-attribution`），下次直接查。
- **用原片自己的剪辑做衔接。** 原片里已有的衔接最可靠：闪白切进闪回，同一手势的硬切（例如父亲递炮的手 → 影子握方块的手）。直接沿用，比自己硬凑的匹配剪辑更有剧情分量。
- **反派和关键事件必须出现。** 漏掉某章的核心人物，懂剧情的观众会立刻指出来（例如终末地 1.1 漏了阮一）。
- **结尾可以回收前文**：各章一镜快速回顾，最后落在全员或主角的英雄镜头上。

## 选镜头：张力优先

- **看实际帧，不看描述。** AI 写的镜头标签会认错角色，也会把多个镜头当成一个。挑镜头用运动峰值帧的联系表（`peaksheet.py`）。
- **有张力的画面**：动作峰值、冲撞与爆发、强构图、带情绪的人物特写（眼睛、伸手）、巨物压迫感。
- **要剔除的画面**：抽象色块、糊成一片的特效、暗场、带大段字幕/UI/宣传字卡的画面、空镜，以及意义不明的平静画面。
- **自动检测出的"镜头"常含内部剪切和叠化**，末尾一两帧可能已经是下一镜。入出点必须在逐帧条带上确认，卡在一个干净的子镜头里。
- **官方过场常把前半段原样重播**，要查重，避免同一画面出现两次。

## 章节衔接：有动机的硬切

| 方式 | 要点 | 案例 |
|---|---|---|
| 同一动作/手势 | 两镜里同一动作在同一阶段 | 带火的手伸向镜头 → 另一个角色的手伸向镜头 |
| 运动延续 | 方向、速度、画面位置一致 | 持刀横向突进 → 另一角色同方向突进；水流向右扫 → 能量向右扫开 |
| 切在闪光上 | 出点在全白或爆闪峰值，入点也从亮处开始 | 最后一击炸成全白 → 下一章交锋的白色爆闪 |
| 图形匹配 | 形状或位置相似 | 圆对圆、眼睛对星球、宽景对宽景 |

怎么找：

1. 用光流把两个镜头池逐帧比对，比较运动方向、速度、主体横向位置和亮度，排出候选对（`mixcut-pipeline` 的 `matchcut.py`）。
2. 分数只做初筛，必须用逐帧条带（`strips.py`）亲眼确认：出点那一帧动作还在，入点那一帧动作已经开始。
   - 反例：一个指向镜头的手势在镜头最后 0.2 秒已经收回，剪点必须提前。
3. 渲染后在每个剪点 T 抽 T-0.25、T-0.05、T+0.02、T+0.25 四帧复查（`framesheet.py`）。

硬切以外的转场一律不用。

## 镜头内的强调：少用才有力

| 手段 | 用法 |
|---|---|
| 冲击帧（1–3 帧反色/白/黑白） | 只给每段最大的几下 |
| 衰减震屏（12–18 px，0.25–0.4 s） | 冲击镜头 |
| 缩放冲击（约 6%，0.25 s 回弹） | 落点 |
| 慢推（4–8%） | 人物特写、英雄镜头 |
| 变速 | 先慢后快冲向落点，或在跳跃顶点放慢 |
| 定格 + 慢推 | 歌词停顿处 |
| 色散 | 极少用，跟冲击帧一起 |

一个镜头最多叠两三种，不是每个剪点都要加特效。

## 开头与结尾

- 开头可以让画面从一条细缝展开。
- 结尾：英雄镜头卡在最后一个重拍上。音乐实际结束处（响度跌到约 -24 dB）直接切断，音频只淡出最后约 0.4 s 防爆音。

## 交付前自查

1. 剪辑表校验通过：全部落在节拍网格上，不越出镜头，没有禁用或重复镜头。渲染前逐镜看源画面条带：入出点不跨进别的子镜头，不落在糊帧、空镜、字幕、界面图形上。
2. 出草稿，用 `video_sheet.py` 做每个片段中点的分镜表，逐个看。落在色块、暗场、原片字幕上的换掉。
3. 每个章节衔接都抽帧确认。
4. 我听不到声音，卡点是按网格算的。如实告诉用户，请用户试听。
5. 用户认可后再出最终版（1080p60，H.264 High，高码率）。
