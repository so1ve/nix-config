# 素材归属与剧情核实

讲"从开服到现在"一类历程的混剪，最容易犯的错是把素材放错章节。用户一眼就能看出来，而且这是最严重的批评。本文是通用方法。具体作品的版本表、资料来源写在项目的 `catalog/story.md`，人物写在 `catalog/characters.md`，都是项目数据，不写进 skill。

## 规则

1. **按画面内容归章节，不按视频发布时间。**
   - 上线宣传片常常提前展示后续版本的角色和场景。带角色名卡的预告最容易暴露这一点。
   - 预告片归它所预告的章节，不归它发布时所在的章节。
   - 特别映像、世界观简报、回顾片不推进剧情，只能用作序章或氛围镜头。
   - 一个视频里也可能混着多个章节的内容，要按镜头逐个判断。
2. **主线和角色剧情分开。**
   - 角色 PV、角色叙事、角色 EP（音乐视频）、角色活动的过场，都算角色剧情。
   - 版本 PV、主线章节过场算主线。
   - 判断依据：官方公告里的版本内容、wiki 的主线任务列表、视频标题前缀（如"干员叙事""EP""过场动画"）。用户默认只要主线；用户点名的例外要记下来。
3. **认人不能靠猜。**
   - 先找带名卡的镜头。
   - 再拿 wiki 立绘、官方角色图对照发色、配饰、武器、面具。
   - 同样的颜色或道具不代表同一个人：同一部 PV 里别的角色可能也用相近的特效（例如同样的绿色玉块阵法）。要看脸、发饰和服装。
   - AI 生成的镜头描述和只读文字的研究子代理都会认错人，结论必须用帧图核对。
4. **拿不准就问用户。** 做一张帧图（每个疑点 4–6 帧），配具体问题，比如"这几镜是不是某某？""这段过场算主线吗？"。玩家用户通常乐意帮忙，答案也最可靠。
5. **把决定写进项目。** 禁用清单（整个视频或单个镜头）要由校验脚本强制执行。分两层：用户明确否掉的镜头进全局清单；"只放主线"这类只对某种剪辑成立的规则进单独的清单，由剪辑表声明。同一批素材以后可能要做角色个人向剪辑，那时角色剧情正是主料。素材目录里的"时期"字段只代表发布时间，不能当作剧情归属。

## 流程

1. **建章节表。** 每个版本或篇章写清：名称（中英）、上线日期、主线章节编号、地点、核心冲突、关键人物和反派。来源是官方公告和 wiki。
2. **给每个素材视频分类**：主线、角色剧情、预告（预告哪一章）、世界观或回顾、宣传或活动。
3. **逐镜头复核**宣传片、预告片这类混杂素材。
4. **列核心人物和事件清单**，确认每一章都有对应画面。漏掉某章的核心人物或反派，懂剧情的观众会立刻指出来。
5. 做帧图，把疑点集中问一次用户。确认后再剪。

## 场景记录与人物档案

读过的东西要落成文件，下次不用重读，也不会凭记忆认错人。

1. **场景记录**：每个源视频一份 `catalog/scenes/<id>.md`。
   - 先跑 `scenes.py <id>`（`mixcut-pipeline`）：它分好场景、标出黑场白闪和与别的视频重复的画面，出读片图，并生成这份文件的骨架。再看读片图，要用的段落用 `strips.py` 细看。
   - 开头写时长、真实帧率（有没有每帧存两遍）、字幕和界面图形情况、主线还是角色剧情。
   - 表格按源视频秒数列出：时间 | 场景（地点、发生了什么）| 人物 | 可用性。
   - 可用性写明原因：字幕、界面图形、名卡、实机视角、别的角色、和别的视频重复的画面（官方 PV 常复用过场）。
   - 原片里有力的硬切（同手势、闪白切闪回、挥刀接爆炸）单独注明，剪的时候保持相邻。
   - 拿不准的标 `?`，用户确认后改掉。
2. **人物档案**：写在项目的 `catalog/characters.md`（项目数据，不写进 skill）。每人记：
   - 外观：发色、耳角、头饰、标记、服装；
   - 武器与招式特效的颜色；
   - 在哪些视频里确认过，靠什么确认（名卡、标题、用户）；
   - 容易混淆的人。
   - 参考框：`- ref: <src> <秒> <x>,<y>,<w>,<h>`，选名卡或用户确认过的正脸。`whois.py` 用它在全部素材里找此人的候选镜头；候选要看图确认。
   - 未确认的推断单独列出。
3. 用户回答过的问题（"这是谁""算不算主线"）当场写进这两处。

## 去哪查

- **官方网站公告**：版本内容、主线章节名和日期最可靠。
- **官方视频频道**：YouTube 用 `yt-dlp --skip-download --print "%(upload_date)s %(title)s %(description)s"` 拿发布日期和简介，简介里常有台词原文。
- **B 站**：空间列表 API 会被拦（-352/412）；`yt-dlp "bilisearch8:关键词"` 短时间内能用。官方视频常按语言分 P。
- **Wiki**：
  - fandom 或 wiki.gg 的版本页、主线任务页、角色页（立绘可以直接下载对照）。
  - BWIKI、萌娘百科、PRTS 一类中文 wiki。
- **社区**：NGA、Reddit、贴吧，用来补充"这段过场是哪一章"。只当线索，以官方和 wiki 为准。
- **官方中文文案**：用 WebSearch 加引号搜原句，以官方视频页和官网公告为准，不要自己翻译英文版。

## 用户截图说"这一镜不要"时

1. 用参考帧定位脚本（见 `mixcut-pipeline`），在成片和源视频里找到它。
2. 对应到剪辑表里的那个片段（源视频 + 镜头编号）。
3. 写进禁用清单，再检查同项目的其他剪辑是否也用了它。
